# Журнал прогонов

Ключ к сравнимости: прогоны сравнимы **только** при одном наборе полей, единиц и версии золотого набора. Несравнимость журнала — почти всегда «считали по разным метрикам». Прогон, не занесённый сюда, не существует (дефект «замер без записи»); решение, опирающееся на прогон, ссылается на его `id`.

## Схема прогона

Каждый прогон заполняет все обязательные поля:

```yaml
id: RUN-<дата>-<буква>        # устойчивый, не меняется
hypothesis: H-...             # какую проверку/гипотезу закрывает (если есть)
stand: local | partner        # на каком стенде
created: 2026-08-14

config:                       # проверяемая конфигурация целиком
  embedder: —
  pooling: —
  chunking: —
  retrieval: —                # dense | hybrid; для hybrid — лемматизация да/нет
  first_stage_top_n: —        # глубина первого этапа: сколько кандидатов ушло в реранкер
  reranker: —
  llm: —
  quantization: —
  k: —                        # сколько чанков подаётся в контекст

golden_set: gs-v2             # версия прибора

metrics:                      # имена из criteria.md; величина ВСЕГДА с единицей
  hit@5:     { value: —, unit: доля }   # ПАРА: hit и recall печатаются только вместе
  recall@5:  { value: —, unit: доля }
  precision@1: { value: —, unit: доля }
  ndcg@5:    { value: —, unit: доля }
  latency_p95: { value: —, unit: сек }
  context_tokens: { value: —, unit: токены }  # суммарный объём поданного контекста
  # метрику на потолке (hit@5) НЕ выбрасывать — у неё любое движение значимо

changed_answers:              # «сколько вопросов изменили ответ» — по каждой метрике
  ndcg@5: —
  recall@5: —

sanity:                       # санитарка ОТДЕЛЬНО, решений из неё не выводим
  result: —
  note: "проверяем, что модель не битая, а не качество поиска"

provenance:
  stand_commit: —             # коммит RAG-stand, чтобы прогон был воспроизводим
  raw: —                      # где лежит сырьё вывода
```

## Прогоны до дисциплины — gs-v1, партия 1 корпуса

Занесены задним числом 19.08.2026. Схема выше к ним не применялась: часть полей тогда не заводилась и восстановлению не подлежит. Форма сокращённая — идентификатор, конфигурация в объёме, который известен, ключевые числа и что прогон дал. **Сравнивать их с прогонами на gs-v2 нельзя**: другой корпус, другой золотой набор, часть метрик на потолке.

Зачем занесены: до этого на прогон нельзя было сослаться — только пересказать. Теперь у каждого есть имя, и роадмап, доказательная база и справочники ссылаются на одно и то же событие.

**Сравнение с [[checks/runs#`RUN-20260809-C` — реранкер и глубина каскада|RUN-20260809-C]]** — тот же набор вопросов, тот же реранкер, корпус вырос со 144 чанков до 1446:

**Дал: потолка больше нет, и цена этого видна.** Метрики партии 1 стояли на потолке, потому что top-50 покрывал треть корпуса — найти верное было почти нечего мешать. > [!warning] Строго говоря, это ещё не базовая линия

Вопросы остались корректными — все ссылки покрыты чанками, иначе прогон бы упал, — но набор не пополнялся под новые документы, и часть корпуса не опрошена ни одним вопросом. Базовая линия ставится на gs-v2 после доразметки (гипотеза `H-001`); до неё эти числа — точка отсчёта для сравнения с собой, а не оценка качества.

## Прогоны по схеме — gs-v2

Пока пусто. Блок прогона печатает сам замер, руками заполняются только те поля, которых программа знать не может — имя гипотезы, буква в идентификаторе и сравнение с предшественником:

```bash
uv run python scripts/evaluate.py --rerank --run-block
```

Первый ожидаемый — базовая линия поиска на gs-v2 (гипотеза `H-001`), после доразметки набора и переключения `evaluate.py` на gs-v2. С него схема заполняется полностью, включая провенанс до коммита стенда.

**Поле `context_tokens` добавлено 17.08.2026** и обязательно для прогонов, сравнивающих способы нарезки (`H-004`, `H-010`, `H-011`, `H-012`): без него прогон с крупными чанками выигрывает у прогона с мелкими просто потому, что подал в контекст больше текста, и сравнение теряет смысл. Обоснование — открытый вопрос 6 в [README.md](README.md).

**Поля `retrieval` и `first_stage_top_n` добавлены 17.08.2026** — по той же причине, но со стороны поиска. `first_stage_top_n` и `k` — разные числа (сколько кандидатов ушло в реранкер против того, сколько чанков попало в контекст), и прогоны с разной глубиной первого этапа несравнимы, даже если `k` у них совпадает. Поле обязательно для `H-003`, `H-009`, `H-013`, `H-014`. Обоснование — блок про `H-014` в [hypotheses.md](hypotheses.md).

**`hit@5` выведен в схему явной парой к `recall@5`** — по правилу пары метрик из [criteria.md](criteria.md). Прогон с заполненной одной и пустой второй считается незаполненным: именно на этом расхождении волт уже однажды получил несравнимые цифры.
