# Журнал прогонов

Ключ к сравнимости: прогоны сравнимы **только** при одном наборе полей, единиц
и версии золотого набора. Несравнимость журнала — почти всегда «считали по разным
метрикам». Прогон, не занесённый сюда, не существует (дефект «замер без записи»);
решение, опирающееся на прогон, ссылается на его `id`.

## Схема прогона

Каждый прогон заполняет все обязательные поля:

```yaml
id: RUN-<дата>-<буква>        # устойчивый, не меняется
hypothesis: H-...             # какую проверку/гипотезу закрывает (если есть)
stand: local | partner        # на каком стенде
created: 2026-08-14

config:                       # проверяемая конфигурация целиком
  embedder: —
  pooling: —
  chunking: —
  retrieval: —                # dense | hybrid; для hybrid — лемматизация да/нет
  first_stage_top_n: —        # глубина первого этапа: сколько кандидатов ушло в реранкер
  reranker: —
  llm: —
  quantization: —
  k: —                        # сколько чанков подаётся в контекст

golden_set: gs-v2             # версия прибора

metrics:                      # имена из criteria.md; величина ВСЕГДА с единицей
  hit@5:     { value: —, unit: доля }   # ПАРА: hit и recall печатаются только вместе
  recall@5:  { value: —, unit: доля }
  precision@1: { value: —, unit: доля }
  ndcg@5:    { value: —, unit: доля }
  latency_p95: { value: —, unit: сек }
  context_tokens: { value: —, unit: токены }  # суммарный объём поданного контекста
  # метрику на потолке (hit@5) НЕ выбрасывать — у неё любое движение значимо

changed_answers:              # «сколько вопросов изменили ответ» — по каждой метрике
  ndcg@5: —
  recall@5: —

sanity:                       # санитарка ОТДЕЛЬНО, решений из неё не выводим
  result: —
  note: "проверяем, что модель не битая, а не качество поиска"

provenance:
  stand_commit: —             # коммит RAG-stand, чтобы прогон был воспроизводим
  raw: —                      # где лежит сырьё вывода
```

## Прогоны

Пока пусто: ни одного прогона в этой дисциплине не занесено. Первый ожидаемый —
базовая линия поиска на gs-v2 (гипотеза `H-001`), после доразметки набора
и переключения `evaluate.py` на gs-v2.

Измеренные до дисциплины ориентиры (партия 1, gs-v1) лежат в `../11-evidence.md`
и `../09-experiments.md` — их не переписывать сюда, а ссылаться.

**Поле `context_tokens` добавлено 17.08.2026** и обязательно для прогонов,
сравнивающих способы нарезки (`H-004`, `H-010`, `H-011`, `H-012`): без него
прогон с крупными чанками выигрывает у прогона с мелкими просто потому, что
подал в контекст больше текста, и сравнение теряет смысл. Обоснование —
открытый вопрос 6 в [README.md](README.md).

**Поля `retrieval` и `first_stage_top_n` добавлены 17.08.2026** — по той же
причине, но со стороны поиска. `first_stage_top_n` и `k` — разные числа
(сколько кандидатов ушло в реранкер против того, сколько чанков попало
в контекст), и прогоны с разной глубиной первого этапа несравнимы, даже
если `k` у них совпадает. Поле обязательно для `H-003`, `H-009`, `H-013`,
`H-014`. Обоснование — блок про `H-014` в [hypotheses.md](hypotheses.md).

**`hit@5` выведен в схему явной парой к `recall@5`** — по правилу пары
метрик из [criteria.md](criteria.md). Прогон с заполненной одной и пустой
второй считается незаполненным: именно на этом расхождении волт уже
однажды получил несравнимые цифры.
