# План проверок (гипотезы)

Что проверяем и в каком порядке. Каждая строка — одно опровержимое заявление,
привязанное к порогу из [criteria.md](criteria.md) и закрываемое прогоном из
[runs.md](runs.md). Формат: **«конфигурация X даёт порог Y при ограничении Z»**.

Приоритет — это порядок проверки, **не** ворота: по цели проекта пайплайн
поднимаем не смотря на ошибки поиска, поэтому «не подтвердилось» здесь — повод
записать разрыв и решить, что дальше, а не остановка.

Перенято из откаченного проекта и переосмыслено; статусы сброшены к факту на
14.08.2026 (прогонов в дисциплине ещё нет).

## Статусы и правила

`open` → `running` → `confirmed` / `refuted`.

- Гипотеза без порога из [criteria.md](criteria.md) недействительна: непонятно,
  что считать успехом.
- Заявление должно быть опровержимым. «Проверить, хорош ли реранкер» — не
  гипотеза; «реранкер поднимает nDCG@5 на gs-v2 при задержке ≤ N с» — гипотеза.
- Закрытая гипотеза ссылается на прогон из [runs.md](runs.md), который её закрыл.
