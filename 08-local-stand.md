# Локальный стенд на MacBook Air M4 (24 ГБ)

Дата: 28.07.2026. Проверено на машине: Apple M4, 24 ГБ, Homebrew установлен,
компоненты стека — нет.

## Зачем

Три причины, в порядке важности:

1. **Снимает блокировку.** Этап 0 в [06-roadmap.md](06-roadmap.md) (доступы
   к Qdrant и VPS партнёра) стопорит всё. Локальный стенд позволяет пройти
   этапы 1–6 самостоятельно и переключиться на инфраструктуру партнёра
   сменой адресов в конфиге.
2. **Дешевле экспериментировать.** Пересоздать коллекцию, снести всё и начать
   заново, попробовать другую модель — на своей машине это минуты и ничьё
   разрешение.
3. **Репетиция форм-фактора для клиента.** Вариант «Mac mini M4» из
   `Business/legal-ai/02-tech.md` перестаёт быть теорией: цифры, полученные
   здесь, переносятся на mini с поправкой в лучшую сторону (у mini активное
   охлаждение).

## Бюджет памяти

| Конфигурация | Память | Комментарий |
|---|---|---|
| Qdrant (сотни чанков) | сотни МБ | Незаметен |
| Эмбеддер 0,6B (bge-m3 / Qwen3-Embedding-0.6B) | ~1–1,5 ГБ | Metal из коробки |
| Реранкер 0,6B (bge-reranker-v2-m3) | ~1,1 ГБ | |
| **Стенд разработки (всё вышеперечисленное)** | **~4 ГБ** | Большой запас |
| + консультант 8B Q4 | +5 ГБ | Комфортно |
| + консультант 14B Q4 | +9 ГБ | Нормально |
| + консультант 24–32B Q4 | +14–18 ГБ | Впритык; всё сразу не помещается — выгружать эмбеддер между шагами |

Нюанс unified memory: GPU по умолчанию не может занять все 24 ГБ — потолок
около двух третей. Поднимается системной настройкой (`iogpu.wired_limit_mb`),
но за счёт ОС; на Air это уже нездоровый режим. Для стенда разработки не нужно.

## Установка

Всё через Homebrew.

**Среда для контейнеров** (Qdrant поставляется docker-образом; на macOS нужен
слой виртуализации — Colima или OrbStack):

```bash
brew install colima docker && colima start --cpu 4 --memory 6 --disk 60
```

`docker` здесь — только CLI-клиент, сама виртуалка — Colima. Альтернатива в
один шаг: `brew install --cask orbstack` (быстрее стартует, платная для
коммерческого использования — проверить условия).

**Qdrant:**

```bash
docker run -d --name qdrant -p 6333:6333 -p 6334:6334 -v ~/qdrant_storage:/qdrant/storage qdrant/qdrant
```

Проверка: `http://localhost:6333/dashboard` — веб-интерфейс с коллекциями
и возможностью выполнять запросы руками.

**llama.cpp** (Metal включён из коробки на Apple Silicon):

```bash
brew install llama.cpp
```

**Python:** системный 3.9 для этого стека староват, ставим uv:

```bash
brew install uv
```

Дальше в папке проекта: `uv init`, `uv add qdrant-client httpx`.

## Запуск моделей

Два отдельных процесса `llama-server` на разных портах — эмбеддер и реранкер
не совмещаются в одном.

**Эмбеддер** (порт 8080):

```bash
llama-server -hf <репозиторий-GGUF-эмбеддера> --embeddings --port 8080 -c 2048 --ubatch-size 2048
```

**Реранкер** (порт 8081):

```bash
llama-server -hf <репозиторий-GGUF-реранкера> --embedding --pooling rank --reranking --port 8081
```

Флаг `-hf` скачивает модель с Hugging Face и кэширует. **Точные имена
репозиториев проверить на HF перед запуском** — они меняются, и у одной модели
бывает несколько конвертаций разного качества (см. предупреждение про
Qwen3-Reranker в [05-retrieval-rerank.md](05-retrieval-rerank.md)).

Кандидаты: эмбеддер — bge-m3 или Qwen3-Embedding-0.6B; реранкер —
bge-reranker-v2-m3 ([03](03-embeddings.md), [05](05-retrieval-rerank.md)).

Про `--ubatch-size`: он ограничивает максимальную длину одного текста для
эмбеддинга. 2048 с запасом покрывает контекстуализированные чанки; при
`512` (значение по умолчанию) длинные чанки обрабатывать нечем.

## Порядок проверки — до всякого кода

Пять минут, экономят часы отладки.

1. **Qdrant жив:** дашборд открывается, `docker logs qdrant` без ошибок.
2. **Эмбеддер отвечает и даёт размерность:**

```bash
curl -s localhost:8080/v1/embeddings -H 'Content-Type: application/json' -d '{"model":"x","input":["тест"]}' | python3 -c "import json,sys; e=json.load(sys.stdin)['data'][0]['embedding']; print('размерность:', len(e))"
```

Полученное число — размерность коллекции Qdrant. Без него дальше не идти.

3. **Санитарная проверка смысла:** три текста — два про одно, один про другое;
   косинус первых двух должен быть заметно выше. Ловит неверный pooling,
   забытые префиксы и неподходящую модель разом.
4. **Реранкер отвечает:** подать один заведомо релевантный документ и один
   заведомо нет — разница в скорах должна быть очевидной. Одинаково ничтожные
   скоры (порядка 1e-23) = битая конвертация GGUF.

## Что переносится на сервер партнёра, а что нет

Главная таблица документа. Локальный стенд — не копия боевой среды, и путать
их дорого.

| Переносится без изменений | Не переносится |
|---|---|
| Код: чанкер, загрузчик, поиск, реранк | **Размерность вектора** — у модели партнёра почти наверняка другая → коллекцию пересоздавать |
| Схема payload и структура пойнтов | Абсолютные значения метрик качества (recall, nDCG) — модель другая, цифры другие |
| Золотой набор вопросов и методика замеров | Время загрузки и индексации — другое железо, у партнёра GPU-индексация |
| Логика чанкинга и контекстуализации | Префиксы и pooling — зависят от конкретной модели |
| Схема SQL и логика извлечения | |

Практический вывод: **обращение к эмбеддеру должно быть за одной функцией**,
адреса и имена моделей — в конфиге, размерность — читаться из ответа API,
а не быть константой в коде. Тогда переезд на VPS партнёра — это правка `.env`,
а не переписывание.

Второй вывод: локальные метрики — это **методика**, а не результат. Они
доказывают, что пайплайн работает и что измерения воспроизводимы; финальные
цифры считаются на модели партнёра.

## Ограничения Air, о которых стоит помнить

**Пассивное охлаждение.** Air без вентилятора: интерактивные запросы (поиск +
реранк) — секунды, троттлинга не будет. Многочасовые пакетные прогоны
(векторизация большого корпуса, извлечение реквизитов по сотням договоров)
приведут к снижению частот. На корпусе из 10 договоров неактуально; помнить
при планировании больших прогонов.

**Наши задачи упираются в prefill, а не в генерацию.** Реранкинг 50 пар,
извлечение полей из страниц договора, эмбеддинги — это «прочитать много,
написать мало». Обработка промпта — вычислительная задача, где Apple Silicon
слабее NVIDIA сопоставимой цены. Генерация упирается в пропускную способность
памяти, у базового M4 она скромная.

**Qdrant на Mac работает только на CPU.** GPU-индексация у него реализована
через Vulkan (NVIDIA/AMD/Intel), Metal не поддерживается. На нашем корпусе
разницы нет — индексация сотен чанков занимает секунды. Разойдётся с сервером
партнёра только на десятках тысяч документов, и это ожидаемо.

## Гигиена данных — завести привычку сразу

Тестовые договоры сгенерированы, ничего страшного в них нет. Но привычки
формируются на них, а применяться будут к документам клиентов.

1. **Рабочая папка — вне синхронизации с iCloud.** На macOS папки Desktop и
   Documents по умолчанию могут синхронизироваться в iCloud Drive. Для проекта,
   чьё главное обещание — «данные не покидают контур», документы клиента,
   уезжающие в облако Apple, — это провал обещания в буквальном смысле.
   Проверить и держать корпус в папке вне синхронизации.
2. **Корпус не коммитить.** В `.gitignore` уже внесены `data/` и `corpus/`.
3. **Никаких облачных API «для сравнения качества».** Соблазн «прогоню тот же
   вопрос в облачной модели, посмотрю разницу» на тестовых данных безобиден,
   на клиентских — то самое нарушение, ради предотвращения которого продукт
   и существует. Разделять эти режимы привычкой, а не силой воли.

Эти три пункта — тот же принцип, что в реестре страхов `Business/03-fears.md`:
свойство конструкции, а не обещание аккуратности.

## Открытые вопросы

1. Какую модель ставить локально — ту же, что у партнёра (если он назовёт),
   или удобную; в первом случае метрики станут сопоставимыми.
2. Нужен ли локально консультант-LLM на этом этапе — для этапов 1–6 нет,
   он понадобится только на сборке ответа.
3. Colima или OrbStack — проверить лицензионные условия OrbStack для
   коммерческого использования.
4. Замерить на своём железе: время векторизации корпуса, время загрузки
   в Qdrant, latency поиска и реранка — это первые собственные цифры проекта.
