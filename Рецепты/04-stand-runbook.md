# Ранбук: развернуть стенд с нуля

> [!info] Длинная форма
> Соседний [01-stand-from-scratch.md](01-stand-from-scratch.md) — короткая
> выжимка для того, кто разворачивал стенд раньше. Здесь та же процедура
> целиком: с предпосылками, ожидаемым выводом каждого шага, откатом
> и разбором отказов. Устройство стенда и обоснования параметров —
> [08-local-stand.md](../08-local-stand.md).

## Когда применять

| Ситуация | Куда идти |
|---|---|
| Новая машина, стенда на ней никогда не было | **сюда** |
| Стенд снесён до основания, `models/` не сохранён | **сюда** |
| Стенд стоит, после перезагрузки не поднят | `./start-stand.sh` — минуты, не часы |
| Стенд поднят, изменился корпус или чанкер | [02. Перезалить корпус](02-reload-corpus.md) |
| Стенд поднят, нужен замер | [03. Прогнать замер](03-run-measurement.md) |

Признак, по которому эти случаи различаются: **есть ли каталог `models/` с восемью гигабайтами**. Если есть — разворачивать с нуля не нужно, и запускать этот ранбук значит потратить три часа на повторное скачивание.

## Что нужно заранее

**Железо и ОС.** macOS на Apple Silicon. Все замеры волта сняты на MacBook Air M4 с 24 ГБ памяти; на другом железе цифры придётся перемерить — [[00-context#Что меняется на другом железе|что именно меняется]].

**Доступы:**

| Что | Зачем | Как проверить, что есть |
|---|---|---|
| SSH-ключ к GitHub | клонировать `Omario-r/rag-stand` | `ssh -T git@github.com` |
| Сеть до huggingface.co | `llama-server -hf` качает модели | `curl -sI https://huggingface.co \| head -1` |
| Homebrew | `llama.cpp` и `uv` | `brew --version` |

**Прав администратора не нужно. Docker не нужен.** Это осознанное свойство конструкции, а не случайность — [[08-local-stand#Решение: без Docker и без прав администратора|почему так]].

**Место на диске:** ~9 ГБ. Из них 8 ГБ — кэш моделей, 69 МБ — бинарник Qdrant, 17 МБ — дашборд.

**Память:** поднятый стенд занимает около 10 ГБ (T-lite ~7,8 ГБ, эмбеддер ~1,6 ГБ, реранкер и Qdrant — остаток). На 24 ГБ помещается, но параллельно с тяжёлой IDE будет тесно.

**Канал — главный лимит.** На VPN ~0,6 МБ/с скачивание идёт так:

| Что | Размер | Время на 0,6 МБ/с |
|---|---|---|
| T-lite-it-2.1 Q6_K | 6,26 ГБ | **~3 часа** |
| Qwen3-Embedding-0.6B Q8_0 | 610 МБ | ~17 минут |
| bge-reranker-v2-m3 Q8_0 | 606 МБ | ~17 минут |
| Бинарник Qdrant | 69 МБ | ~2 минуты |
| Дашборд Qdrant | 17 МБ | ~30 секунд |

Итого **около трёх с половиной часов**, из которых собственно работы — минут двадцать. Скачивание генеративной модели ставится первым и оставляется работать.

## Процедура

### 1. Убедиться, что порты свободны

```bash
for p in 6333 6334 8080 8081 8084; do printf "%s: " "$p"; lsof -nP -iTCP:$p -sTCP:LISTEN >/dev/null 2>&1 && echo "занят" || echo "свободен"; done
```

**Вывод (дословно), стенд не поднят:**

```
6333: свободен
6334: свободен
8080: свободен
8081: свободен
8084: свободен
```

Занятый порт на этом шаге — это либо уже поднятый стенд, либо чужой процесс. `start-stand.sh` занятый порт молча пропустит («уже слушает :6333, пропускаю») и создаст иллюзию, что всё поднялось.

### 2. Инструменты

```bash
brew install llama.cpp uv
```

**Вывод (дословно), проверка версий на развёрнутом стенде:**

```
version: 10280 (61881b1f7)
built with AppleClang 21.0.0.21000101 for Darwin arm64
uv 0.12.1 (Homebrew 2026-07-31 aarch64-apple-darwin)
```

Версия llama.cpp существенна: замер предельной длины текста снят на сборке `b10280`, и на другой сборке правило «длину задаёт `-c`, а не `--ubatch-size`» нужно переснимать — [[03-embeddings#Флаги, которые нас касаются|разбор флагов и замер]].

### 3. Клонировать стенд

```bash
git clone git@github.com:Omario-r/rag-stand.git ~/Development/Home/RAG-stand
```

Каталог принципиален: `~/Development` не синхронизируется с iCloud, в отличие от `Desktop` и `Documents` на этой машине. В синхронизируемой папке окажутся и база Qdrant, и корпус — [[08-local-stand#Гигиена данных|гигиена данных]].

Стенд — отдельный репозиторий, а не часть волта: [[08-local-stand#Стенд под собственным гитом|почему так]].

### 4. Создать каталоги, которых нет в гите

```bash
cd ~/Development/Home/RAG-stand && mkdir -p bin static models storage snapshots logs data cache
```

Из клона приходят скрипты, код пайплайна и тестовый корпус. Всё тяжёлое и всё состояние закрыто гитигнором и создаётся здесь. Отдельно про `data/`: там живёт `contracts.sqlite` второго контура, и лежит она **не в `cache/`** намеренно — таблица `pending` хранит подтверждённое человеком и прогоном не восстанавливается, а каталог с именем «кэш» рано или поздно удаляют не глядя ([[08-local-stand#SQL-база второго контура|разбор]]).

### 5. Поставить скачиваться генеративную модель

Самый долгий шаг, поэтому он идёт раньше всего остального. `start-stand.sh` модель **не качает** — он ждёт её и падает по таймауту через три минуты.

```bash
cd ~/Development/Home/RAG-stand && ./run-llm.sh
```

Команда не вернёт управление: скачав файл, она поднимет сервер на 8084. Три часа она занимает терминал — дальнейшие шаги делаются в соседнем окне. Прогресс виден в её собственном выводе.

Шаги 6–9 выполняются, пока модель качается.

### 6. Qdrant

```bash
curl -sL -o /tmp/qdrant.tar.gz https://github.com/qdrant/qdrant/releases/download/v1.19.0/qdrant-aarch64-apple-darwin.tar.gz
```

```bash
shasum -a 256 /tmp/qdrant.tar.gz
```

Ожидаемая сумма — `4e279a80cc1ebe73e859318ff86375af54c123887dd7ae46605c0eb6cb7c44e8`. Сумма перенесена из [01-stand-from-scratch.md](01-stand-from-scratch.md) и заново не снималась: архив на этой машине не сохранён, распакован только бинарник. **Проверить: если сумма не совпадёт, сверять с релизом на GitHub, а не считать несовпадение поломкой ранбука.**

```bash
tar xzf /tmp/qdrant.tar.gz -C ~/Development/Home/RAG-stand/bin && chmod +x ~/Development/Home/RAG-stand/bin/qdrant
```

```bash
~/Development/Home/RAG-stand/bin/qdrant --version
```

**Вывод (дословно):**

```
<jemalloc>: option background_thread currently supports pthread only
qdrant 1.19.0
```

Строка про `jemalloc` — не ошибка, она печатается при каждом запуске.

Бинарник подписан ad-hoc, Gatekeeper его пропускает; карантина нет, потому что скачан через `curl`, а не браузером.

### 7. Дашборд Qdrant

Нативный бинарник, в отличие от docker-образа, статику дашборда не содержит — она берётся отдельным релизом.

```bash
curl -sL -o /tmp/qdrant-ui.zip https://github.com/qdrant/qdrant-web-ui/releases/download/v0.2.16/dist-qdrant.zip
```

Ожидаемая сумма — `4446f0cea024078011c78cd24a592c9b563656d15205818563fa6b22d394dd29`, перенесена оттуда же и заново не снималась.

```bash
unzip -q /tmp/qdrant-ui.zip -d /tmp/qdrant-ui && rm -rf ~/Development/Home/RAG-stand/static && mv /tmp/qdrant-ui/dist ~/Development/Home/RAG-stand/static
```

Проверка, что легла нужная версия:

```bash
cd ~/Development/Home/RAG-stand && python3 -c "import json;print(json.load(open('static/qdrant-web-ui.spdx.json'))['name'])"
```

**Вывод (дословно):** `qdrant-web-ui@0.2.16`

### 8. Конфигурация и ключи

`.env` из образца, права 600, ключи случайные:

```bash
cd ~/Development/Home/RAG-stand && umask 077 && printf 'QDRANT_URL=http://127.0.0.1:6333\nQDRANT_GRPC_PORT=6334\nEMBEDDER_URL=http://127.0.0.1:8080\nRERANKER_URL=http://127.0.0.1:8081\nLLM_URL=http://127.0.0.1:8084\nQDRANT_API_KEY=%s\nLLAMA_API_KEY=%s\n' "$(openssl rand -hex 24)" "$(openssl rand -hex 24)" > .env
```

**Переменных должно быть семь, а не пять.** Без `LLM_URL` второй контур падает на `KeyError: 'LLM_URL'` — не при запуске стенда, а позже, на `scripts/extract-demo.py`, и связь с недописанным `.env` к тому моменту не очевидна.

```bash
cd ~/Development/Home/RAG-stand && ls -l .env && grep -c '=' .env
```

**Схема формата** (значения выдуманы, важны права и число строк):

```
-rw-------  1 user  staff  241 01 Sep 12:00 .env
7
```

Ключи нужны даже на петле: без ключа любая открытая вкладка браузера может слать запросы на `127.0.0.1:6333` и, например, удалить коллекцию — [[08-local-stand#2. Ключи даже на localhost|обоснование]].

Контуров два и работают они одновременно: локальный описан в `.env`, контур партнёра — в `.env.partner`, и он **накладывается поверх**, а не заменяет. Этот ранбук поднимает только локальный.

### 9. Python-окружение

```bash
cd ~/Development/Home/RAG-stand && uv sync
```

Проект требует Python 3.10 (`.python-version`); `uv` при необходимости скачает его сам. Зависимости из `uv.lock` — `numpy`, `python-docx`, `pyyaml`, `qdrant-client`, в dev-группе `pytest`.

Проверка:

```bash
cd ~/Development/Home/RAG-stand && uv run python -c "import qdrant_client, numpy, yaml, docx; print('окружение собрано')"
```

**Вывод (дословно):** `окружение собрано`

Без этого шага рецепты [02](02-reload-corpus.md) и [03](03-run-measurement.md) не пойдут: они начинаются с `uv run python scripts/…`.

### 10. Поднять стенд

К этому моменту `run-llm.sh` из шага 5 уже скачал модель и держит порт 8084. Останавливать его не нужно — `start-stand.sh` увидит занятый порт и пропустит этот сервис. Эмбеддер и реранкер скачаются здесь же, по 17 минут каждый.

```bash
cd ~/Development/Home/RAG-stand && ./start-stand.sh
```

**Схема формата** (номера процессов выдуманы, важны сами строки):

```
Поднимаю стенд:
  qdrant: запущен (pid 12345), лог logs/qdrant.log
  embedder: запущен (pid 12346), лог logs/embedder.log
  reranker: запущен (pid 12347), лог logs/reranker.log
  llm: уже слушает :8084, пропускаю

Жду готовности (модели грузятся в память ~10–60 с)...
Готово: Qdrant + эмбеддер + реранкер + модель отвечают.
```

Скрипт ждёт до трёх минут. На первом запуске эмбеддер и реранкер за это время не успеют скачаться — скрипт завершится с ненулевым кодом и напечатает статусы. Это ожидаемо: дождаться скачивания по `tail -f logs/embedder.log` и запустить `./start-stand.sh` повторно.

## Проверка — до всякого кода

```bash
cd ~/Development/Home/RAG-stand && ./check-stand.sh
```

Пять проверок, около пяти минут. Что ловит каждая:

| # | Проверка | Что ловит | Признак беды |
|---|---|---|---|
| 1 | Три сервиса отвечают | не поднялось, порт занят чужим | код не 200 |
| 2 | Без ключа — 401, из локальной сети — недоступен | ошибку конфигурации безопасности | `⚠️ ОТКРЫТ`, `ДОСТУПЕН ⚠️` |
| 3 | Размерность, норма и косинус на трёх текстах | неверный pooling, забытые префиксы, неподходящую модель | разрыв ≤ 0,1 |
| 4 | Реранкер различает два документа | битую конвертацию GGUF | оба скора ничтожны |
| 5 | `/props` и тексты растущей длины | расхождение скрипта запуска с реальностью, малый контекст | предел ниже 2000 токенов |

Третья проверка устроена так: два текста про одно и то же **разными словами** («неустойка 0,1% за просрочку доставки» и «пеня одна десятая процента в сутки за задержку») и один про другое (санитарное состояние помещения). Разные слова принципиальны — на одинаковых проверка выродилась бы в сравнение подстрок.

Пятая проверка спрашивает у сервера `/props` вместо того, чтобы верить скрипту запуска. Причина конкретная: оборванная обратным слешем команда в `run-*.sh` молча теряет аргументы, и сервер поднимается не с той конфигурацией, что написана в файле — [[18-pitfalls#Оборванная команда в скрипте запуска|как это уже случалось]].

Дальше стенд пустой: коллекции в Qdrant нет. Наполнение — [02. Перезалить корпус](02-reload-corpus.md).

## Откат

| Что откатывать | Команда | Что останется |
|---|---|---|
| Остановить сервисы | `./stop-stand.sh` | данные в `storage/`, модели в `models/` |
| Сбросить базу Qdrant | `./stop-stand.sh && rm -rf storage/ snapshots/ .qdrant-initialized` | модели, `.env`, окружение |
| Переделать конфигурацию | сгенерировать `.env` заново | всё остальное; ключ в дашборде придётся ввести новый |
| Снести стенд целиком | `./stop-stand.sh && rm -rf ~/Development/Home/RAG-stand` | ничего |

**`models/` при сносе стоит сохранить отдельно.** Восемь гигабайт на этом канале — три с половиной часа; всё остальное разворачивается за двадцать минут.

```bash
mv ~/Development/Home/RAG-stand/models ~/Development/models-backup
```

Откат безопасен на любом шаге: ничего за пределами каталога стенда процедура не трогает, кроме `brew install` и файлов в `/tmp`.

## Если не сработало

Порядок разбора — от дешёвого к дорогому.

**1. Логи.** Каждый сервис пишет свой:

```bash
cd ~/Development/Home/RAG-stand && tail -30 logs/*.log
```

**2. Известные грабли.** [18-pitfalls.md](../18-pitfalls.md) — на что уже наступали и по какому признаку узнаётся. Три частых случая:

| Симптом | Вероятная причина |
|---|---|
| Сервер поднялся, но ведёт себя не как в скрипте | оборванная обратным слешем команда в `run-*.sh`, аргументы потеряны |
| Реранкер выдаёт нулевые скоры | битая конвертация GGUF |
| Эмбеддер съел гигабайты сверх ожидаемого | `--parallel` не 1, KV-кэш умножен на число слотов |

**3. Устройство и параметры.** [[08-local-stand#Ключевые параметры и почему они такие|таблица параметров]] — что задаёт каждый флаг и что сломается, если его поменять.

**4. Троттлинг, а не ошибка.** Air без вентилятора: многочасовой пакетный прогон снижает частоты, и медленный результат может быть не поломкой — [[08-local-stand#Ограничения Air, о которых стоит помнить|ограничения Air]].

## Открытые вопросы

1. Контрольные суммы архивов Qdrant и дашборда перенесены из рецепта 01 и на этой машине заново не снимались — переснять при следующем развёртывании.
2. Вывод `check-stand.sh` в этом ранбуке описан таблицей признаков, а не дословно: стенд на момент написания был не поднят. Снять дословный вывод и заменить таблицу на него.
3. Второй контур (`data/contracts.sqlite`) в процедуру не входит: каталог создаётся, база — нет. Решить, часть ли это развёртывания стенда или отдельная процедура.
