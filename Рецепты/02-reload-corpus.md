# Перезалить корпус

> [!info] Рецепт — живая инструкция
> Как устроена загрузка и почему параметры такие — [04-qdrant.md](../04-qdrant.md), раздел «Быстрая пакетная загрузка». Здесь только последовательность.

Нужен, когда изменился корпус, чанкер или адресация чанков.

## Когда `--recreate`, а когда без него

| Что менялось | Команда | Почему |
|---|---|---|
| добавились документы | без флага | `id` детерминированный, свои чанки перезапишутся |
| правился чанкер или адресация | `--recreate` | иначе пойнты старой нарезки останутся в коллекции и будут находиться поиском |
| менялась модель эмбеддера | `--recreate` | другая размерность или другой пулинг — прежние векторы несовместимы |

Пересоздание сейчас стоит 0,03 с, поэтому по умолчанию выбирается оно: накопление надгробий от перезаливок дороже. Правило перестанет работать на тысяче договоров, когда пересоздание станет переиндексацией ~48 000 чанков.

## Порядок

Стенд поднят, `.env` загружен:

```bash
cd ~/Development/Home/RAG-stand && ./start-stand.sh && ./check-stand.sh
```

Загрузка:

```bash
cd ~/Development/Home/RAG-stand && uv run python scripts/load-qdrant.py --recreate
```

Скрипт печатает число чанков и покрытие золотого набора. **Непокрытая ссылка занижает `recall` молча** — метрика посчитается, а вопрос окажется нерешаемым по построению; на этой строке останавливаться и разбираться.

## Проверить, что легло

```bash
cd ~/Development/Home/RAG-stand && uv run python scripts/check-chunks.py
```

Дальше — глазами через дашборд `http://127.0.0.1:6333/dashboard`: половина «поиск не работает» оказывается «в payload не то, что мы думали».

Ждать `status=green` бесполезно — он зелёный с самого начала. Смотреть `indexed_vectors_count` против `points_count` ([[11-evidence#4. `indexing_threshold` считается на сегмент, а не на коллекцию|почему]]).
