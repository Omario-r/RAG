# Паттерны использования RAG

## Обычный (naive) RAG

Прямой линейный сценарий: вопрос пользователя → эмбеддинг вопроса →
поиск релевантных чанков → генерация ответа на их основе. Один проход,
без промежуточных решений — система всегда выполняет один и тот же
фиксированный шаг поиска для любого вопроса.

Такой подход хорошо работает, когда вопрос сформулирован достаточно
конкретно и полностью покрывается одним поиском. Он хуже справляется
с составными вопросами («сравни условия по продукту A и продукту B»,
«что нужно сделать сначала — X или Y, и почему») — единственный проход
поиска по всему составному вопросу целиком может не найти всех нужных
частей ответа, потому что запрос как единый вектор смешивает смысл
нескольких разных под-вопросов.

## Агентный (agentic) RAG

Между пользователем и поисковым контуром добавляется промежуточный
слой — агент, который сам анализирует запрос и решает, как его
обработать, прежде чем выполнять поиск:

- может разбить составной вопрос на несколько более простых
  под-запросов и выполнить поиск по каждому отдельно;
- может выбирать между разными инструментами (не только векторный
  поиск, но, например, обращение к SQL-базе, вызов внешнего API);
- после получения результатов по всем под-запросам синтезирует из них
  единый связный ответ, а не просто конкатенирует найденные фрагменты.

Это делает систему более гибкой и устойчивой к тому, как реально
формулируют вопросы живые пользователи (не всегда одним чётким
предложением), но добавляет сложность архитектуры и дополнительные
вызовы модели (сам агентный слой рассуждений — это тоже обращения
к LLM), а значит — дополнительную задержку и стоимость.

## Как выбирать

Обычный RAG — разумная стартовая точка, если типичные вопросы
пользователей конкретны и укладываются в один поисковый запрос
(например, бот поддержки с чёткими, предсказуемыми типами вопросов).
Агентный RAG оправдан, когда пользователи задают составные,
многосоставные или неоднозначно сформулированные вопросы, для которых
одного прохода поиска систематически недостаточно.
