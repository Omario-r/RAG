# Векторные базы данных

## Чем векторная БД отличается от обычной

Обычная база данных устроена как картотека по точному совпадению:
найти запись по конкретному ключу — имени, идентификатору, дате.
Векторная база устроена принципиально иначе — это скорее карта, на
которой документы расположены по смыслу: близкие по теме объекты
находятся рядом, далёкие по теме — далеко друг от друга. Когда приходит
вопрос, система ищет не по точному совпадению ключевых слов, а по
близости в этом смысловом пространстве — среди эмбеддингов документов
находятся те, что ближе всего к эмбеддингу запроса.

Технически задача векторной БД — эффективно решать задачу поиска
ближайших соседей (nearest neighbor search) среди миллионов и десятков
миллионов векторов за приемлемое время, что требует специализированных
индексных структур, а не линейного перебора.

## Основные варианты инструментов

- **Chroma** — локальная база, ориентированная на простоту запуска и
  прототипирование. Не требует отдельной инфраструктуры и настройки,
  подходит для тестов и небольших проектов на старте.
- **Pinecone** — управляемая облачная база, рассчитанная на серьёзную
  продакшен-нагрузку; провайдер берёт на себя масштабирование и
  эксплуатацию.
- **Qdrant** — open source база, написанная на Rust, с акцентом на
  производительность и гибкость настройки; можно развернуть
  самостоятельно (self-hosted) или использовать облачную версию.
- **pgvector** — расширение для PostgreSQL, добавляющее векторный
  поиск в уже существующую реляционную базу. Удобно, если в проекте
  уже используется PostgreSQL и не хочется вводить отдельную
  специализированную СУБД.

## Как выбирать

Для старта и прототипирования локальная база без конфигурации и
затрат на инфраструктуру — самый низкий порог входа. Для продакшена
с высокой нагрузкой имеет смысл сравнивать управляемые облачные
решения (минимум эксплуатационных забот, но зависимость от провайдера
и его тарифов) против self-hosted опций (больше контроля и потенциально
ниже стоимость на масштабе, но требуется своя эксплуатация). Если
в проекте уже есть PostgreSQL, расширение вроде pgvector может быть
самым простым способом добавить векторный поиск без введения новой
системы хранения.
