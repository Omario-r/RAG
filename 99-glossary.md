## Базовые

- **Эмбеддинг (вектор)** — массив чисел фиксированной длины, в который модель
  сворачивает смысл текста. Похожие по смыслу тексты → близкие векторы.
- **Размерность** — длина этого массива (1024, 1536, 4096). Задаётся моделью,
  фиксируется при создании коллекции, потом не меняется.
- **Косинусная близость** — мера похожести двух векторов (угол между ними),
  от −1 до 1. Основная метрика для текста. У нормированных векторов совпадает
  со скалярным произведением.
- **Чанк** — кусок документа, единица индексации и поиска. У нас — пункт
  договора с метаданными.
- **RAG** (Retrieval-Augmented Generation) — схема «сначала найди нужные куски
  документов, потом дай их модели, чтобы она отвечала по ним, а не по памяти».

## Векторная БД

- **Qdrant** — векторная БД, которую мы используем. Написана на Rust, есть
  REST (6333) и gRPC (6334), веб-дашборд.
- **Коллекция** — аналог таблицы. Хранит пойнты одной размерности с одной
  метрикой расстояния.
- **Пойнт (point)** — единица хранения: `id` + вектор(ы) + payload.
  Аналог строки.
- **Payload** — JSON-довесок к пойнту: текст чанка, номер договора, номер
  пункта, даты. По нему фильтруют, его возвращают в выдаче.
- **Upsert** — вставка-или-обновление по `id`. Основная операция записи.
- **Сегмент** — внутренняя единица хранения Qdrant; коллекция состоит из
  сегментов, оптимизатор их сливает, чистит и индексирует.
- **Оптимизатор** — фоновый процесс Qdrant: строит индексы, сливает сегменты
  (merge), вычищает удалённое (vacuum).
- **indexing_threshold** — порог в килобайтах: сегменты меньше него не
  индексируются. `0` = индексацию не строить. Наш главный рычаг ускорения
  массовой загрузки.
- **Снапшот** — консистентная копия коллекции; страховка перед экспериментами.

## Индексы и поиск

- **ANN** (Approximate Nearest Neighbor) — приблизительный поиск ближайших
  соседей. Приблизительный не значит плохой: точный перебор на больших
  коллекциях невозможен.
- **HNSW** — конкретный ANN-алгоритм: многослойный граф соседства. Быстрый
  поиск ценой дорогого построения. Отсюда «insert тяжелее select».
- **m, ef_construct** — параметры построения графа HNSW (связей на узел,
  ширина поиска при построении). Влияют на качество индекса и время сборки.
- **hnsw_ef** — ширина поиска при запросе. Рычаг «точность против скорости»,
  меняется без переиндексации.
- **Filterable HNSW** — способность Qdrant применять фильтр внутри обхода
  графа, а не после. Поэтому `limit=10` с фильтром вернёт 10 подходящих.
  Альтернативы (пост-фильтр) ломаются молча: возвращают три результата
  вместо десяти, не давая ошибки.
- **Селективность фильтра** — доля базы, которую фильтр пропускает.
  Определяющий параметр: поведение при 50 % и при 0,1 % отличается
  качественно. Наш `doc_id` — доли процента.
- **Квантизация** — сжатие векторов (например до 4 или 1 бита) ради экономии
  памяти; сжатая копия в RAM, точная — на диске.
- **Полный перебор (flat, `exact=true`)** — сравнение запроса со всеми
  векторами. Не запасной вариант, а рабочий режим примерно до десяти
  тысяч объектов. **Режим стенда:** HNSW не построен, поиск 8 мс.
  На целевом корпусе («портфель из тысяч договоров», ~48 чанков
  на договор) порог пересекается около двухсот договоров — индекс
  будет, и его поведение надо проверять заранее.
- **ANN-recall** — совпадение выдачи индекса с точным перебором по тем же
  векторам. Меряет инженерию (`hnsw_ef`, квантизация, фильтры), а не смысл.
  Просевший ANN-recall выглядит снаружи как «модель стала хуже».
- **Tombstone («надгробие»)** — пометка «удалён» вместо физического удаления
  узла графа: удалить по-настоящему значит разорвать связность. Накопление
  роняет качество поиска без всякой ошибки.
- **Hit@k** (Success@k) — доля запросов, где в первые k попал **хоть один**
  верный документ. Главная метрика первого этапа каскада.
- **Recall@k** — доля **верных документов**, попавших в первые k. Это не то
  же, что Hit@k: вопрос с тремя верными ответами, из которых найден один,
  даёт Hit@k = 1,0 и Recall@k = 0,33. На нашем корпусе величины разошлись
  почти вдвое, поэтому считаются и печатаются обе
  ([[05-retrieval-rerank#Метрики]]).
- **MRR / nDCG** — метрики, учитывающие позицию правильного ответа в выдаче.

## Второй эшелон

- **Би-энкодер** — модель, которая кодирует текст в вектор независимо от
  запроса (все эмбеддинг-модели). Быстро, потому что векторы посчитаны заранее.
- **Кросс-энкодер (реранкер)** — модель, которая читает пару (запрос, документ)
  вместе и оценивает релевантность. Точнее, но считается только в момент
  запроса.
- **Каскад** — схема «дешёвый широкий отбор → дорогое точное сужение»:
  Qdrant top-50 → реранкер top-5.
- **Sparse-вектор** — разрежённый вектор (в основном нули), где ненулевые
  позиции соответствуют конкретным словам. Основа BM25-поиска.
- **BM25** — классический алгоритм полнотекстового ранжирования: редкие слова
  весят больше частых. Хорош там, где вектора слабы — номера, ИНН, термины.
- **Гибридный поиск** — совместное использование плотного (смысл) и
  разрежённого (слова) поиска.
- **RRF** (Reciprocal Rank Fusion) — способ объединить две выдачи по позициям,
  а не по несопоставимым оценкам.

## Инференс

- **llama.cpp** — движок запуска моделей на C++; `llama-server` даёт
  HTTP-API, в том числе OpenAI-совместимый.
- **GGUF** — формат файлов моделей для llama.cpp.
- **Квантизация модели (Q4, Q8)** — сжатие весов модели ради памяти и
  скорости, ценой небольшой потери качества. Не путать с квантизацией
  векторов в Qdrant.
- **Pooling** — способ свернуть векторы всех токенов в один вектор текста:
  `mean`, `cls`, `last`; для реранкера — `rank`. Неверный pooling молча
  портит качество.
- **Префиксы / инструкции** — служебные приставки к тексту, которых требуют
  некоторые модели (`query:` / `passage:`, `search_query:`, `Instruct:`).
  Забытый префикс = тихая деградация поиска.
- **ubatch (физический батч)** — сколько токенов модель обрабатывает за раз;
  для эмбеддингов ограничивает максимальную длину одного текста.
- **Контекст (`-c`)** — максимальное окно модели в токенах.

## Извлечение данных

- **Structured extraction (структурированное извлечение)** — получение из
  свободного текста заполненной структуры данных (номер, дата, стороны, сумма)
  для записи в SQL.
- **Constrained decoding** — ограничение вывода модели грамматикой: невалидный
  по схеме ответ физически не может быть сгенерирован. Не гарантирует, что
  значения верные, — только что формат верный.
- **GBNF** — формат грамматик llama.cpp (расширенная форма Бэкуса — Наура),
  в который конвертируется JSON Schema.
- **`response_format`** — параметр запроса к llama.cpp/OpenAI-совместимому API,
  задающий схему ответа. Важно: схема ограничивает вывод, но **не попадает в
  промпт** — структуру надо описать словами отдельно.
- **Валидация цитаты** — проверка кодом, что фрагмент, на который ссылается
  модель, дословно присутствует в документе. Основной барьер против выдуманных
  значений.
- **Денормализация** — намеренное дублирование полей (реквизиты и в SQL,
  и в payload Qdrant) ради возможности фильтровать без обращения ко второй базе.
- **Человек в контуре (human-in-the-loop)** — схема, где неуверенные значения
  не пишутся в базу молча, а уходят оператору на подтверждение.

## Про наши документы

- **Золотой набор** — список контрольных вопросов с заранее известными
  правильными пунктами договоров. Инструмент измерения качества поиска.
- **Контекстуализация чанка** — дописывание «адреса» (договор, раздел) в текст
  перед векторизацией.
- **Small-to-big (parent-document)** — искать по мелким чанкам, отдавать в
  контекст крупные родительские разделы.
- **Late chunking** — сначала прогнать длинный текст через модель, потом
  резать эмбеддинги; сохраняет контекст. У нас в резерве.
