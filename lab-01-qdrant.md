# Лаб 1. Потыкать Qdrant руками

Этап 1 из [06-roadmap.md](06-roadmap.md). Справочник по Qdrant —
[04-qdrant.md](04-qdrant.md); здесь только последовательность действий.

**Цель:** не «сделать по шагам», а понять три вещи — что такое коллекция,
пойнт и payload, и как посмотреть, что реально лежит в базе. Полдня по оценке,
на практике меньше.

Работаем через `curl`, а не через Python-клиент, сознательно: видно сырой API,
и не надо настраивать окружение. Клиент придёт на этапе 2.

## Подготовка

Поднять стенд, если не поднят:

```bash
~/Development/Home/RAG-stand/start-stand.sh
```

Загрузить адреса и ключи в текущую оболочку:

```bash
source ~/Development/Home/RAG-stand/.env
```

Определить короткую обёртку, чтобы не повторять ключ в каждой команде:

```bash
qd() { curl -s -H "api-key: $QDRANT_API_KEY" -H 'Content-Type: application/json' "$@" | python3 -m json.tool; }
```

Обёртка живёт до закрытия окна терминала. Открыли новое — повторить `source`
и определение `qd`.

Дашборд: http://127.0.0.1:6333/dashboard — попросит API-ключ, он в `.env`.
Держите открытым во второй вкладке: после каждой команды полезно посмотреть
на то же самое глазами.

## Шаг 1. Что вообще есть в базе

```bash
qd $QDRANT_URL/collections
```

Ожидаемо пусто: `{"collections": []}`. Это нормальное начало.

## Шаг 2. Создать игрушечную коллекцию

Размерность 4 вместо настоящих 1024 — чтобы векторы можно было писать руками
и предсказывать результат поиска. Это и есть смысл упражнения.

```bash
qd -X PUT $QDRANT_URL/collections/toy -d '{"vectors": {"size": 4, "distance": "Cosine"}}'
```

**Что заметить:** размерность и метрика задаются один раз и меняются только
пересозданием коллекции. Отсюда требование волта не хардкодить размерность
в коде, а читать её из ответа эмбеддера.

Посмотреть, что получилось:

```bash
qd $QDRANT_URL/collections/toy
```

В ответе: `status`, `points_count`, `indexed_vectors_count`, полный конфиг.
Запомните эти поля — к ним возвращаемся на шаге 8.

## Шаг 3. Залить пойнты

Шесть чанков из воображаемых договоров. Векторы подобраны так, что видно
три темы: первая координата — «ответственность», вторая — «оплата»,
третья — «сроки».

```bash
qd -X PUT "$QDRANT_URL/collections/toy/points?wait=true" -d '{"points": [
  {"id": 1, "vector": [0.9, 0.1, 0.0, 0.0], "payload": {"doc_id": "TR-114", "clause": "4.2", "topic": "ответственность", "doc_type": "перевозка",      "date_expire": "2026-12-31T00:00:00Z", "amount": 4500000, "text": "За просрочку доставки Перевозчик уплачивает неустойку 0,1%"}},
  {"id": 2, "vector": [0.8, 0.2, 0.0, 0.0], "payload": {"doc_id": "TR-118", "clause": "6.1", "topic": "ответственность", "doc_type": "экспедирование", "date_expire": "2026-10-15T00:00:00Z", "amount": 1200000, "text": "Ответственность Экспедитора ограничена суммой 500 000 рублей"}},
  {"id": 3, "vector": [0.0, 0.9, 0.1, 0.0], "payload": {"doc_id": "TR-114", "clause": "3.1", "topic": "оплата",          "doc_type": "перевозка",      "date_expire": "2026-12-31T00:00:00Z", "amount": 4500000, "text": "Оплата производится в течение 10 банковских дней"}},
  {"id": 4, "vector": [0.1, 0.85, 0.05, 0.0], "payload": {"doc_id": "TR-120", "clause": "3.4", "topic": "оплата",         "doc_type": "аренда_ТС",      "date_expire": "2027-03-01T00:00:00Z", "amount": 900000,  "text": "Арендная плата вносится ежемесячно до 5 числа"}},
  {"id": 5, "vector": [0.0, 0.0, 0.9, 0.1], "payload": {"doc_id": "TR-118", "clause": "2.3", "topic": "сроки",            "doc_type": "перевозка",      "date_expire": "2026-10-15T00:00:00Z", "amount": 1200000, "text": "Срок доставки груза — 5 календарных дней с даты погрузки"}},
  {"id": 6, "vector": [0.0, 0.1, 0.85, 0.05], "payload": {"doc_id": "TR-120", "clause": "8.2", "topic": "сроки",          "doc_type": "аренда_ТС",      "date_expire": "2027-03-01T00:00:00Z", "amount": 900000,  "text": "Договор действует до 1 марта 2027 года"}}

```

`wait=true` здесь намеренно: на шести пойнтах это ничего не стоит, зато
результат виден сразу. При массовой загрузке будет наоборот — `wait=false`
([04-qdrant.md](04-qdrant.md#быстрая-пакетная-загрузка)).

Проверить количество:

```bash
qd -X POST $QDRANT_URL/collections/toy/points/count -d '{"exact": true}'
```

Должно быть 6.

## Шаг 4. Идемпотентность — выполните ту же команду ещё раз

Повторите команду из шага 3 без изменений, затем снова посчитайте:

```bash
qd -X POST $QDRANT_URL/collections/toy/points/count -d '{"exact": true}'
```

**По-прежнему 6, а не 12.** Это и есть `upsert`: пойнт с существующим `id`
перезаписывается, а не добавляется. Отсюда практический вывод волта —
детерминированный `id` (UUID5 от `doc_id` + номер пункта) даёт бесплатную
защиту от дублей при повторной загрузке договора во время отладки.

Попробуйте изменить `text` у пойнта с `id: 1` и залить снова — увидите, что
значение заменилось.

## Шаг 5. Поиск

Ищем «про ответственность» — вектор, близкий к первой координате:

```bash
qd -X POST $QDRANT_URL/collections/toy/points/query -d '{"query": [0.9, 0.1, 0.0, 0.0], "limit": 3, "with_payload": true}'
```

Должно получиться так (проверено):

```
id=1  score=1.0000  ответственность  перевозка
id=2  score=0.9910  ответственность  экспедирование
id=4  score=0.2254  оплата           аренда_ТС
```

**Что заметить в `score`:** при косинусной метрике это близость, больше =
ближе, максимум 1. Обратите внимание, что даже нерелевантный пойнт получает
какой-то score — «ничего не нашлось» векторный поиск не отвечает никогда.
Он всегда возвращает `limit` ближайших, даже если все они мимо. Отсюда два
следствия из волта: нужен реранкер, и абсолютное значение score сравнивать
между разными запросами бессмысленно.

Попробуйте поискать «про сроки» и «про оплату», меняя вектор запроса:

```bash
qd -X POST $QDRANT_URL/collections/toy/points/query -d '{"query": [0.0, 0.0, 0.9, 0.1], "limit": 3, "with_payload": true}'
```

## Шаг 6. Payload-индексы

Индексы по полям payload нужны для быстрой фильтрации. Волт требует создавать
их **до** массовой загрузки — здесь порядок нарушен сознательно, чтобы
увидеть, что команда та же самая.

```bash
qd -X PUT $QDRANT_URL/collections/toy/index -d '{"field_name": "doc_type", "field_schema": "keyword"}'
```

```bash
qd -X PUT $QDRANT_URL/collections/toy/index -d '{"field_name": "date_expire", "field_schema": "datetime"}'
```

```bash
qd -X PUT $QDRANT_URL/collections/toy/index -d '{"field_name": "amount", "field_schema": "float"}'
```

## Шаг 7. Фильтры — самое важное в этой лабе

Тот же поисковый запрос, но только по договорам перевозки:

```bash
qd -X POST $QDRANT_URL/collections/toy/points/query -d '{"query": [0.9, 0.1, 0.0, 0.0], "limit": 3, "with_payload": true, "filter": {"must": [{"key": "doc_type", "match": {"value": "перевозка"}}]}}'
```

Пойнт 2 (экспедирование) исчез, хотя по смыслу был вторым.

**Ключевое, ради чего этот шаг:** вернулось столько подходящих, сколько
попросили, а не «три ближайших, из которых один прошёл фильтр». Фильтр
применяется внутри обхода графа — это filterable HNSW из
[04-qdrant.md](04-qdrant.md). Именно поэтому связка «сузили по реквизитам,
потом искали смысл» работает одним запросом, а не двумя.

Диапазон по дате — «истекающие до конца 2026»:

```bash
qd -X POST $QDRANT_URL/collections/toy/points/query -d '{"query": [0.0, 0.9, 0.1, 0.0], "limit": 5, "with_payload": true, "filter": {"must": [{"key": "date_expire", "range": {"lt": "2027-01-01T00:00:00Z"}}]}}'
```

Два условия сразу — перевозка **и** дороже 2 млн:

```bash
qd -X POST $QDRANT_URL/collections/toy/points/query -d '{"query": [0.9, 0.1, 0.0, 0.0], "limit": 5, "with_payload": true, "filter": {"must": [{"key": "doc_type", "match": {"value": "перевозка"}}, {"key": "amount", "range": {"gt": 2000000}}]}}'
```

Останутся пойнты 1 и 3: пойнт 5 — тоже перевозка, но на 1,2 млн.

Попробуйте заменить `must` на `should` (хотя бы одно условие) и на `must_not`.
Это три кирпича, из которых собираются все фильтры.

## Шаг 8. Посмотреть, что реально лежит

`scroll` — обход без всякого поиска. На отладке бесценен: половина случаев
«поиск не работает» оказывается «в payload лежит не то, что мы думали».

```bash
qd -X POST $QDRANT_URL/collections/toy/points/scroll -d '{"limit": 3, "with_payload": true, "with_vector": true}'
```

**Первая неожиданность:** векторы вернулись не те, что клали. Вместо
`[0.9, 0.1, 0, 0]` придёт `[0.9938837, 0.11043153, 0, 0]`. Это не ошибка —
при метрике Cosine Qdrant нормирует векторы на входе (приводит длину к 1),
потому что у нормированных векторов косинус равен скалярному произведению,
а оно считается быстрее. Направление сохранено, а значит и все расстояния.
Связь с [03-embeddings.md](03-embeddings.md): наш эмбеддер и так отдаёт
нормированные векторы, так что на реальных данных разницы не будет видно.

`next_page_offset` в ответе — с чего продолжать обход; передаётся параметром
`offset` в следующий запрос. Так листается вся коллекция.

Состояние коллекции:

```bash
qd $QDRANT_URL/collections/toy
```

**Вторая неожиданность:** `indexed_vectors_count` равен нулю, хотя пойнтов
шесть и `status: green`. Это не поломка. `indexing_threshold` в этой сборке —
10 000 КБ, и сегменты меньше порога не индексируются: на таком объёме полный
перебор быстрее графа HNSW. Поиск при этом работает и даже точнее обычного,
потому что перебор точный, а HNSW приблизительный.

Запомните это поле: на настоящем корпусе нулевой `indexed_vectors_count`
означает ровно обратное — забытый `indexing_threshold=0` после массовой
загрузки, то есть линейный перебор на каждом запросе.

## Шаг 9. Снапшот

Страховка перед экспериментами с параметрами: переиндексация корпуса дороже,
чем кажется.

```bash
qd -X POST $QDRANT_URL/collections/toy/snapshots
```

```bash
ls -lah ~/Development/Home/RAG-stand/snapshots/toy/
```

**Третья неожиданность:** снапшот шести пойнтов весит около 350 МБ. Qdrant
резервирует файлы сегментов заранее, и в снапшот попадает всё зарезервированное,
а не только полезные данные. На реальном корпусе доля накладных расходов
становится незаметной, но на игрушечной коллекции выглядит дико.

Не забыть удалить после лабы, иначе 350 МБ будут лежать зря:

```bash
rm -rf ~/Development/Home/RAG-stand/snapshots/toy
```

## Шаг 10. Снести и убедиться, что это дёшево

```bash
qd -X DELETE $QDRANT_URL/collections/toy
```

```bash
qd $QDRANT_URL/collections
```

Снова пусто. Пересоздать коллекцию — секунды, и это правильное отношение
к ней на этапе экспериментов: коллекция расходный материал, ценность —
в коде пайплайна и в золотом наборе вопросов.

## Готовность этапа

Отмечать закрытым, когда можете без подсказки ответить:

1. Чем коллекция отличается от пойнта и что такое payload.
2. Почему нельзя поменять размерность, не пересоздав коллекцию.
3. Что произойдёт при повторной загрузке пойнта с тем же `id`.
4. Почему `limit` с фильтром возвращает столько подходящих, сколько попросили.
5. Как посмотреть, что реально лежит в базе, если поиск ведёт себя странно.
6. Что означает `indexed_vectors_count: 0` и когда это тревожный знак.
7. Почему из базы вернулся не тот вектор, который в неё клали.

## Если что-то не так

| Симптом | Причина |
|---|---|
| `401 Unauthorized` | Не выполнен `source .env` или не определена `qd` в этом окне |
| `Connection refused` | Стенд не поднят — `start-stand.sh` |
| `Wrong input: Vector dimension error` | Вектор не из 4 чисел |
| Поиск возвращает не то, что ждали | Посмотреть `scroll` — скорее всего в payload или векторе не то, что думали |
| Пойнтов вдвое больше | Не тот случай: при одинаковых `id` этого не бывает. Значит `id` разные |
