# Действующие решения

Решения о том, как ведётся `RAG-система/`. Здесь стоят те, что действуют
дальше; разбор отдельного разговора остаётся в журнале. Файл заведён 05.09.2026,
когда роль «Коллега» написала о контуре 2 «писать неоткуда», хотя решение писать
по источникам базы знаний было принято 01.09.2026 и лежало в журнале на строке
1705 из 2842.

Журнал хронологичен и читается с хвоста, поэтому действующее решение уходит из
поля зрения вместе с хроникой того же дня. Здесь оно стоит вне даты.

**Строка на решение.** Отмена или изменение переписывает строку целиком, история
не копится: файл ограничен числом действующих решений. Полная запись с разбором
остаётся в журнале, столбец «записано» указывает дату, по которой она ищется.

**Основание обязательно.** Решение без основания через месяц выглядит как
произвол и переоткрывается — правило 5 из `README.md`.

| База пишется как справочник для себя и для обучения | внешнего читателя нет | 01.09.2026 |
| Перед письмом узла читается соответствующий раздел старой базы | 21.08.2026 узел написан из головы и вышел беднее источника | 01.09.2026 |

## Как называются вещи

| Решение | Основание | Записано |
|---|---|---|
| Контур — поток, узел — шаг контура | слово «узел» стояло в волте в двух смыслах: шаг контура и узел стенда с колонкой ☑ | 01.09.2026 |
| Таблица «В каком это состоянии» в `README.md` не трогается | колонка ☑ — вердикт человека о владении | 01.09.2026 |
| Отрезок нарезки называется чанком | одна вещь называлась тремя словами; выбрано по чтению Романа | 05.09.2026 |
| Словарь ведётся со столбцом запрещённых синонимов | по этому столбцу волт проверяется одной командой; без проверки словарь разошёлся бы с волтом | 05.09.2026 |
| Чистка терминов идёт по `RAG-система/` и по речи роли, `База знаний/` не трогается | старая база остаётся рабочей на время наполнения новой | 03.09.2026 |
| Переименование по всему волту откладывается, пока текущий документ не дочитан | текст не должен двигаться под читателем | 05.09.2026 |
| Придуманное ролью стоит в словаре с прочерком в столбце сообщества и меняется свободно | у таких слов нет внешнего употребления, с которым надо считаться | 05.09.2026 |

## Как идёт работа над текстом

| Решение | Основание | Записано |
|---|---|---|
| Читаемый документ по ходу вычитки не правится, пункты копятся в `<документ>-вычитка.md` | правка под чтением двигает текст под читателем | 05.09.2026 |
| Вопросы задаются только по текущему документу, пока он не дочитан | иначе вычитка расползается на весь волт | 05.09.2026 |
| Сверка с сообществом делается при заведении термина | держать актуальным весь словарь дорого, наружу это ходит субагентом | 05.09.2026 |
| Узлы пишутся по одному, в порядке очереди, без параллельности | основание в журнале не названо | 03.09.2026 |
| Коммит после каждого узла | обрыв сессии не должен стоить работы | 03.09.2026 |
| Правила письма читаются до первой строки нового текста | правила, прочитанные на входе сессии, сами не применяются | 03.09.2026 |
| Ссылки на источники уходят в сноски: в теле только номера | ссылка в теле рвёт чтение, проверяемость числа при этом сохраняется | 04.09.2026 |
| Когда появится карточка источника в `Библиотека/`, в сноску добавляется вики-ссылка на неё | исходные источники читать никто не будет, для этого запланирован конспект | 04.09.2026 |
| Числа по нескольким позициям прозой не идут: таблица при двух-трёх признаках, список при одном | числа прозой ломают чтение; проза перераспределяется во вводку и замыкание | 04.09.2026 |
| Критерий «стало больше строк — правка неверна» к таблицам не применяется, считать надо слова | у таблицы есть шапка и разделитель, каждая позиция стоит на своей строке | 04.09.2026 |
| Дублирование между связанными уровнями допустимо, повторение укрепляет знание | установка Романа | 03.09.2026 |
| Список и таблица по уровням не растаскиваются: пункт раскрывается ниже, сам список остаётся целым | правило об уровнях относится к описанию узла | 01.09.2026 |

## Как устроена структура

| Решение | Основание | Записано |
|---|---|---|
| Служебного в документе по теме нет, карта переноса живёт в `Коллега/перенос-старой-базы.md` | служебное внутри темы для Романа мусор | 01.09.2026 |
| Узел, переросший файл, становится папкой, обзорный файл кладётся внутрь под тем же именем | входящие вики-ссылки продолжают работать без правки | 03.09.2026 |
| Тема, режущая несколько узлов, пишется одним файлом в `Сквозное/` | раскладка по узлам разорвала бы чтение по имени модели | 04.09.2026 |
| Эмбеддеры и пересортировщики описываются в одном файле с генераторами | у них другая система имён, и различие видно только рядом | 04.09.2026 |
| Висящие вики-ссылки на ненаписанные узлы — норма стадии | контуры 1–3 написаны не целиком | 03.09.2026 |
| Пометка о переносе ставится в старой базе поузлово, когда узел закрыт в новой | основание в журнале не названо | 03.09.2026 |
