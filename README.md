# RAG-lab — семантический поиск по договорам в закрытом контуре

**Точка входа в волт.** Здесь — что это за проект, как он устроен и где что лежит. Состояние работ — в [06-roadmap.md](06-roadmap.md), статус этапа меняется только там.

## Что за проект

Семантический поиск по договорам в закрытом контуре: юрист спрашивает «где условия о простое транспорта под погрузкой» и получает не список файлов, а конкретные пункты конкретных договоров. Без облачных API — документы наружу не уходят.

Строится **работающий продукт на своём железе**: разбор документа, нарезка на пункты, векторизация, загрузка в Qdrant, поиск, реранкер, ответ, извлечение реквизитов в SQL. Всё поднято локально на MacBook Air M4 — Qdrant, эмбеддер, реранкер, генеративная модель.

**Установка проекта — продукт и экспертиза, а не эксперимент под чужой сервер.** Пайплайн должен работать целиком на той машине, что есть. Про каждое решение записано основание, про каждую цифру — чем получена, про каждый узел — чем меряется. Переносимость на другое железо — не цель, а свойство: важно знать, **какие выводы держатся, а какие придётся перемерить**. Обе рамки развёрнуты в [00-context.md](00-context.md), там же раздел «Что меняется на другом железе».

Бизнес-часть — ниши, сегменты, экономика — живёт отдельным волтом `~/Development/Home/Business`. Здесь только техника.

## Как это работает

Два контура. Подготовка — редко и долго, запрос — часто и быстро:

```
договор → текст → чанки (пункты) → векторы → Qdrant        [офлайн]
вопрос  → вектор → top-50 → реранкер → top-5 → ответ       [онлайн]
```

Тяжёлую работу делаем один раз при загрузке, чтобы запрос отрабатывал за доли секунды. Разбор целиком, включая то, **где в этом пайплайне ломается качество** (чаще всего в чанкинге, а не в модели), — [01-pipeline.md](01-pipeline.md).

Второй контур, независимый от поиска: формальные реквизиты договора извлекаются моделью по жёсткой схеме и складываются в SQL — [07-extraction.md](07-extraction.md). Он опаснее поиска: неверно найденный пункт юрист заметит, неверно извлечённую сумму — нет.

## Узлы пайплайна

Пайплайн работает сквозным образом на локальном стенде: договор → чанки → векторы → Qdrant → поиск → реранкер → извлечение. Ниже он разложен на семь узлов — это общая ось волта: у каждого узла есть теория в базе знаний, практика в справочниках корня и своя команда на стенде. Состояние этапов и что осталось — [06-roadmap.md](06-roadmap.md).

| **Ответ** | не определено | — | — | **узла нет** — теория написана целиком, практики ноль |
| **Извлечение** | доля заполненных, доля прошедших цитат | 16 полей из 18, все 16 с проверенной цитатой, 74 с/документ, воспроизводимо побайтно | `RUN-20260810-A` | **низкая** — эталона нет, accuracy не мерена |

**Все цифры, кроме строки «Поиск и реранк», сняты на партии 1 — 144 чанка.** Текущая коллекция вдесятеро больше, и на ней тот же золотой набор даёт `hit@5` 0,562 вместо 1,000 ([[runs#`RUN-20260820-A` — тот же золотой набор на выросшем корпусе|RUN-20260820-A]]). Перемерить узлы по одному — работа, которая ещё не сделана.

Колонка «прогон» — имя замера в журнале [checks/runs.md](runs.md): по нему находится конфигурация целиком, все метрики и условия. Колонка «уверенность» — оценка того, можно ли опереться на число, а не самого числа. Метрики поиска выглядят отлично и при этом годятся только для отлова поломки: `hit@5` = `hit@50` = 1,000 на корпусе из 144 чанков. Что этими цифрами делать запрещено — [[11-evidence#Что запрещено делать с этими цифрами|11-evidence]].

Другие площадки в таблицу не входят: работа идёт на своём стенде, остальное — места для будущих экспериментов, вынесены [[Архив/Партнёр/README|отдельной папкой]].

### Запустить

Стенд — `~/Development/Home/RAG-stand/`, отдельный репозиторий:

```bash
./start-stand.sh                            # Qdrant + эмбеддер + реранкер + модель
uv run python scripts/load-qdrant.py        # загрузить корпус
uv run python scripts/evaluate.py --rerank  # посчитать метрики
```

## Как вести волт

Двенадцать правил, без которых документы разъезжаются. Первые четыре — про то, что где лежит; остальные — про честность записи и про сцепку со стендом.

1. **Статус — только в [06-roadmap.md](06-roadmap.md)**, в таблице и в разделе
этапа. Здесь статуса нет намеренно.
2. **Жанры не смешивать.** «Как устроено» — справочники 01–10; «почему так
решено» — [12-decisions.md](12-decisions.md); «чем доказано, с цифрами» — [11-evidence.md](11-evidence.md); «что и когда прогоняли» — [09-experiments.md](09-experiments.md). Их смешение раздуло `08-local-stand.md` до 51 КБ, а этот файл — до 57.
3. **Ответы с других площадок** сначала в [банк вопросов](02-questions.md),
затем разносятся по профильным документам — маршрут указан там же в конце.
4. **Каждый документ заканчивается «Открытыми вопросами»** — это рабочий
список, а не украшение: закрытый вопрос вычёркивается, новый дописывается.
5. **Решение без основания** через месяц выглядит как произвол
и переоткрывается. Строка в журнале решений — с датой и основанием.
6. **Помечать непроверенное.** Всё, что взято из статей и не подтверждено
на нашем стенде, несёт пометку «проверить». Цифра из чужого блога — гипотеза, а не результат.
7. **Помечать, что за блок перед читателем.** Примеры вывода команд
подписываются: **Вывод (дословно)** · **Выжимка** (показано не всё) · **Схема формата** (значения выдуманы). Выжимка без команды, которая её производит, недопустима — читатель сверяет свой экран с документом и принимает расхождение за поломку.
8. **Ссылка на раздел — только вики-ссылкой.** На документ целиком — обычная
markdown-ссылка `[04-qdrant.md](04-qdrant.md)`. На раздел — `[[04-qdrant#5. Параметр wait|текст ссылки]]`: волт читается в Obsidian, а markdown-якорь там не переходит. Переименование заголовка ломает все ссылки на него, искать их `grep -rn '\[\['`.

9. **Узловой справочник открывается разделом «Как стоит сейчас».** Снимок
фактической конфигурации с указанием файла стенда, откуда он снят. Без него читатель не отличает «так у нас сделано» от «так вообще бывает» — а после выноса теории в базу знаний в справочнике остаются оба жанра. Приём, который не применён, помечается прямо под своим заголовком: **«У нас не используется»**. Пометка идёт **под** заголовком, а не в нём: переименование заголовка ломает все вики-ссылки на него.
10. **Расхождение волта со стендом записывается, а не терпится.** Реестр —
[[06-roadmap#Расхождения волта со стендом|06-roadmap.md]]. Замеренное, но не применённое — долг; молчаливое расхождение превращает справочник в художественную литературу.

11. **У замера есть имя.** Прогон заносится в [checks/runs.md](runs.md)
и получает идентификатор `RUN-<дата>-<буква>`; роадмап, доказательная база, хроника экспериментов и таблица узлов ссылаются на это имя, а не пересказывают замер. Цифры целиком живут в прогоне, на месте оставляется только ключевое число. Связность проверяется скриптом:

```bash
python3 tools/check-links.py && python3 tools/check-runs.py && python3 tools/check-labs.py
```

Три прохода: целость ссылок и разметки во всех слоях, связность прогонов, дисциплина лаб.

12. **Потолок вместо роста вглубь.** Документ длиннее ~400 строк или папка
   больше 8 файлов означает «делить», а не «дописать ещё раздел». Делить
   сначала **по жанру**, а не по теме: спросить, сколько жанров живёт внутри.
   Приём взят из [[15-vault-method#Johnny.Decimal — потолок как приём|Johnny.Decimal]];
   строки считаются после склейки переносов (`python3 tools/unwrap.py`).
